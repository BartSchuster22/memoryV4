# MemoryV4 QA10 Acceptance Gates

QA10/10 means the ten gates below pass as automated, runnable acceptance criteria and emit a machine-readable scorecard. The scorecard should be produced by `make qa10` at `build/qa10-scorecard.json` or an equivalent documented path.

Until a gate is implemented, the harness must mark it `pending` or `skipped` with an explanation. It must not silently count unimplemented gates as passing.

## Scorecard contract

Target JSON shape:

```json
{
  "score": 10,
  "max_score": 10,
  "status": "pass",
  "commit": "<git sha>",
  "generated_at": "2026-06-28T00:00:00Z",
  "gates": [
    {
      "id": 1,
      "name": "migrations",
      "status": "pass",
      "evidence": ["command output or artifact path"],
      "notes": "fresh and upgrade paths passed"
    }
  ]
}
```

Allowed gate statuses:

- `pass`
- `fail`
- `pending`
- `skipped`

A release is QA10/10 only when all ten gates are `pass`.

## Gate 1: migrations

Pass criteria:

- Migrations from `0001` through current target version run on a fresh database.
- Upgrade from a captured real-V3 fixture succeeds.
- Re-running migrations is a no-op.
- Every migration has a down path for objects it introduced.
- Additive-only invariant is preserved: no destructive rewrite of governed core tables.

Suggested command:

```bash
make qa10-gate-1
```

Evidence:

- P2 implementation: `app/migrations.py` defines reversible migrations through `0012_health_findings`.
- Automated gate command: `make qa10-gate-1` / `python3 -m pytest -q tests/test_migrations_p2.py`.
- Coverage: fresh database migration log, seeded V3-like upgrade fixture, rerun/no-op assertion, additive-only down-path verification, `promotion_log` and `health_findings` idempotent uniqueness, and sqlite-vec feature detection with portable fallback table.

## Gate 2: storage-seam parity

Pass criteria:

- Core code depends on the Store port, not direct SQLite calls.
- `SqliteStore` is the only implemented adapter.
- Captured pre-seam workload returns byte-identical governed results through the new Store port.
- SQLite-specific FTS, pragmas, SQL syntax, and vec0 usage do not leak above the adapter.
- No Postgres implementation is shipped.

Suggested command:

```bash
make qa10-gate-2
```

Evidence:

- parity fixture output;
- static check or test proving no direct database imports above adapter;
- explicit confirmation that Postgres is a documented future slot only.

## Gate 3: retrieval quality

Pass criteria:

- Hybrid retrieval recall@5 is at least the keyword baseline plus 15% relative improvement on the accepted evaluation set.
- Paraphrase queries that keyword search misses return relevant records through the hybrid path.
- Candidate gathering happens before final limiting.
- Lexical-only fallback works when vector search is unavailable or times out.

Suggested command:

```bash
make qa10-gate-3
```

Evidence:

- evaluation set path;
- baseline scores;
- hybrid scores;
- degraded/fallback test output.

## Gate 4: governance ranking

Pass criteria:

- Governance prior is bounded within `[0.6, 1.4]` or the documented equivalent bounds.
- Equal-relevance `canonical/live` records are nudged above equal-relevance `active` records.
- A highly relevant `evidence/working` record remains retrievable and is not hidden by governance sorting.
- Ranking behavior is covered by property tests or fixed ranking fixtures.

Suggested command:

```bash
make qa10-gate-4
```

Evidence:

- property test output;
- fixture showing canonical nudge;
- fixture showing evidence/working retrieval remains possible.

## Gate 5: supersession and contradiction integrity

Pass criteria:

- No dangling `superseded_by` references.
- Role and lifecycle validators run on every write path.
- Supersession preserves old and new records with lineage.
- Health worker flags conflicting `canonical/live` pairs.
- Contradictions never auto-overwrite or auto-promote canonical records.

Suggested command:

```bash
make qa10-gate-5
```

Evidence:

- supersession integrity test;
- validator coverage report;
- contradiction fixture showing finding creation only.

## Gate 6: provenance and orphan scan

Pass criteria:

- 100% of distilled records carry source refs.
- Artifact-backed task canvas node ids resolve to raw refs.
- Orphan scan detects injected orphan records, relations, artifacts, and node refs.
- Orphan scan has zero false positives on a clean database fixture.

Suggested command:

```bash
make qa10-gate-6
```

Evidence:

- source-ref coverage report;
- node resolution test;
- injected orphan test;
- clean fixture scan.

## Gate 7: idempotence and decay safety

Pass criteria:

- Re-running distillation creates zero duplicate promoted/candidate records for the same source refs.
- Re-running health checks creates zero duplicate findings for the same kind/ref set.
- Dedup threshold is covered by tests.
- Confidence decay emits findings for review only.
- Decay does not alter retrieval order.

Suggested command:

```bash
make qa10-gate-7
```

Evidence:

- `promotion_log` uniqueness test;
- `health_findings` uniqueness test;
- dedup threshold test;
- retrieval-order-before/after-decay fixture.

## Gate 8: scope isolation

Pass criteria:

- Query at scope X returns only ancestor-or-equal records plus curated public records when explicitly enabled.
- Query at scope X never returns sibling org/project/agent/user/session records.
- Lexical and vector lanes apply identical scope filters.
- API keys cannot request outside their allowed scope subtree.
- Distillation and health workers never write to `public`.
- Default tenant queries do not read `public`.

Suggested command:

```bash
make qa10-gate-8
```

Evidence:

- multi-tenant fixture matrix;
- sibling leak negative tests;
- public opt-in tests;
- auth scope-denial tests;
- worker public-write rejection tests.

## Gate 9: security

Pass criteria:

- Every route except `GET /health` enforces scoped keys.
- Token comparison is constant-time.
- Capabilities are checked for mutation, promotion, supersession, backup, restore, and public admin actions.
- Non-loopback service startup without keys warns or fails closed according to policy.
- Error responses do not leak sibling tenant existence.

Suggested command:

```bash
make qa10-gate-9
```

Evidence:

- route auth matrix;
- constant-time comparison test or static assertion;
- capability-denial tests;
- startup warning/fail-closed test;
- no-leak error tests.

## Gate 10: durability

Pass criteria:

- Backup/restore round trip succeeds with checksum verification.
- Restore is overwrite-guarded.
- WAL/concurrent writer behavior is covered.
- Records, FTS rows, and record embeddings stay consistent after fault injection.
- Dual-run parity replay completes cleanly before any future cutover.

Suggested command:

```bash
make qa10-gate-10
```

Evidence:

- backup artifact checksum;
- restore verification log;
- overwrite guard test;
- concurrent writer test;
- fault-injection consistency test;
- dual-run parity replay report.

## Release rule

A phase may ship only when the gates relevant to that phase are implemented and passing, with all other gates honestly marked pending/skipped. MemoryV4 is not QA10/10 until all ten gates pass together in one scorecard from the target commit.
