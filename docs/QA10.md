# MemoryV4 production QA10

`make qa10` is an executable production-critical scorecard. It runs ten independent
pytest gates and writes `build/qa10-scorecard.json`. The command exits non-zero on the
first failed gate; a checked-in or hand-written status cannot make the gate pass.

## Production-critical gates

| # | Gate | Required evidence |
|---|---|---|
| 1 | Authentication and permissions | Authentication, all action permissions, least privilege, explicit delegation, and canonical-create denial tests pass. |
| 2 | Scope isolation | Tenant, project, agent, user, and session ancestor visibility and sibling denial pass across list, direct-read, and search paths. |
| 3 | Write policy and promotion | `team_editable`, `author_only`, `admin_only`, and `immutable` enforcement; canonical restrictions; reason/version/idempotency requirements pass. |
| 4 | Lifecycle and supersession | Archive, expiry, exact restoration, atomic supersession chains, stale-version rejection, and concurrency tests pass. |
| 5 | Pagination, filtering, and search | Deterministic pagination, cursor/filter binding, graph filters, lexical search, and context aggregation pass. |
| 6 | Concurrency, idempotency, and retries | Concurrent create, transition, supersession, and finding-resolution claims commit exactly once. Adapter retry policy is tested by UNIFY. |
| 7 | Audit success and denial | Successful mutations, denied requests, delegated actors, reason metadata, and payload/credential redaction pass. |
| 8 | Content limits and malformed input | Bounded content, source references, structured JSON, and scope paths reject oversized data; extra fields and malformed JSON fail closed. |
| 9 | Migrations and rollback | Fresh migration, upgrades, checksums, strict-prefix validation, reversible rollback, and injected up/down failure atomicity pass. |
| 10 | Backup, restore, restart, and crash recovery | Manifest verification, offline restore, interrupted restore, committed-WAL abrupt exit, and CLI round-trip pass. |

## External release gates

The complete Phase 11 release also requires the owning UNIFY repository's full QA for:

- the MemoryV4 adapter, scope/actor mapping, contract pinning, normalized errors, and
  safe/idempotent retry behavior;
- UNIUI read and governed-edit workflows, permission gating, concurrency conflicts,
  truthful empty/unavailable states, and accessibility;
- framework-facing Memory tools, framework bearer scopes, forced `active/working`
  candidates, stable idempotency, audit redaction, and the absence of promotion tools.

A production acceptance run additionally records live private-network topology,
invalid-auth rejection, both framework identities, a governed write/replay/update/
version-conflict flow, audit evidence, a verified backup and isolated restore, and a
service restart/recovery smoke. These live checks are release evidence; they do not
replace deterministic source tests.

## Explicit non-goals

The following future capabilities are not production-critical requirements of the
locked SQLite v1 contract and are not mislabeled as failed QA gates: vector/RRF search,
replication/PITR, autonomous health workers, public curation, MemoryV3 parity/cutover,
and a Postgres store. MemoryV3 adoption remains a separate explicitly approved phase.
