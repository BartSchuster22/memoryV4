# MemoryV4 QA10 Gates

`make qa10` is the project-level evidence command for the ten MemoryV4 acceptance gates. D0 intentionally records the gate inventory and emits a pending JSON scorecard until downstream implementation slices add executable checks.

## Command

```bash
make qa10
```

Current D0 output path:

```text
build/qa10-scorecard.json
```

## Gates

1. Migrations: 0001 through 0012 are idempotent, every `up` has a `down`, fresh database and upgrade-from-V3 paths are covered.
2. Storage seam parity: `SqliteStore` returns byte-identical results to the captured pre-seam V3 workload; no SQLite-specific behavior leaks above the Store port.
3. Retrieval quality: hybrid recall@5 beats keyword baseline by at least 15% and paraphrase queries succeed where keyword-only lookup fails.
4. Governance ranking: bounded `[0.6, 1.4]` governance multiplier; canonical/live gets a nudge but top-relevance evidence/working remains retrievable.
5. Supersession and contradiction integrity: no dangling supersession links, role/lifecycle validation on every write path, contradiction findings never auto-overwrite canonical records.
6. Provenance and orphan scan: distilled records carry `source_refs`, canvas node ids resolve, orphan scan catches injected orphans with zero false positives on a clean database.
7. Idempotence and decay safety: repeated distillation/health runs create no duplicates; decay is a review flag only and does not change retrieval order.
8. Scope isolation: scope X returns only ancestor-or-equal records plus curated public records; sibling branches never leak; workers never write public.
9. Security: every route except `GET /health` enforces scoped keys using constant-time comparison and scope-aware authorization.
10. Durability: backup/restore round trip covers records, FTS, embeddings, and checksums; WAL/concurrent writer and fault-injection consistency checks pass.

## D0 status

D0 is allowed to be pending on the functional gates because it only establishes the repository, container skeleton, CI/test entrypoints, documentation stubs, and operational guardrails. Later implementation cards must replace the placeholder scorecard with executable per-gate evidence.
